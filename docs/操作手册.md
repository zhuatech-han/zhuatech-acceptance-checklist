## 建立项目

收到供应商的交付通知后，先点击“按场景新建清单”，选择“网站或小程序上线”“企业管理系统交付”或“源码与运维资料移交”，填写项目名称、交付版本和核对日期。已有项目可从“选择项目”切换。检查点是提醒，不代表每项都在合同范围内；可删除不适用的提示，或用“新增检查项”补上实际约定。

## 逐项记录

先在“项目约定标准及依据”写明合同条款、需求编号、版本和可判定条件，再填写结果。选择“通过”时应填写测试证据位置；选择“未通过”时写清问题、证据、处理动作和责任人；选择“不适用”时保留双方确认的范围依据。需要复测时记录日期，复测后更新结果和证据。

“记录待补”会提示已选择结果但缺少的关键材料。顶部统计仅计算手填状态，不代替验收决定。最终是否验收、遗留问题是否可以带入质保，应按项目约定由双方确认。

例如验收“官网咨询表单”：在“项目约定标准及依据”填写“需求 V1.0 第 3.2 项：手机提交后后台能收到”；用手机提交测试内容，如果后台没有收到，选择“未通过”，在“证据位置”填测试截图文件名，在“问题与处理”写“手机提交后后台无记录，供应商检查表单接口”，填写责任人和复测日期。不要把真实账号密码写入记录。

## 保存与导出

填写内容自动保存在当前浏览器。发现问题后，点击“导出待整改清单”取得只含“未通过”项目的 CSV，核对后发给供应商；完整记录可另行导出 CSV 或使用“打印 / 存为 PDF”。供应商修复后，回到原项目复测并更新结果。此工具没有多人实时同步，协作时以导出的文件和双方确认的版本为准。

如需保留全部项目或换设备，使用“导出 JSON 备份”；另一浏览器可导入此文件。**导入会替换当前浏览器中的全部项目**，请先备份原有记录。使用无痕窗口或清理浏览器数据前也应先备份。

CSV、JSON 与打印结果可能包含合同、系统和客户资料。请仅通过适合该项目的渠道分享，并由项目负责人确认接收对象。
